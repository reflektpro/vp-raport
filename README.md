# Электронный рапорт ГУ ВП

`index.html` — рапорт на взыскание, `povyshenie.html` — рапорт на повышение, `otchet.html` — еженедельный отчёт, `vygovor.html` — приказ о предупреждении или выговоре. Баллы повышения лежат в `promo-rules.js`, отработка по уставу — в `vygovor-rules.js`: для подразделения и вида взыскания в приказ попадают все пункты.

Сайт-бланк: боец заполняет рапорт прямо на «листе», жмёт «Отправить», и в Discord прилетает картинка документа с подписью и печатью, пинг руководства и ссылка на боди-камеру. Всё бесплатно: сайт на GitHub Pages, пересылка через Cloudflare Worker.

## Файлы
- `index.html`, `style.css`, `app.js` — сам сайт
- `config.js` — настройки: роли, шапка, текст печати, адрес отправки
- `emblem.png` — эмблема
- `worker.js` — пересыльщик для Cloudflare (прячет ссылку вебхука)

## Запуск за 10 минут
1. **Вебхук.** Discord → настройки канала → Интеграции → Вебхуки → Новый → «Копировать URL».
2. **Worker.** dash.cloudflare.com (бесплатно) → Workers & Pages → Create → Hello World → Edit code → вставь `worker.js` → Deploy.
   В Settings → Variables добавь (тип Secret):
   - `WEBHOOK_URL` — ссылка вебхука
   - `ROLE_IDS` — `1321249388965793844,1321249411954774128,1321249413024452608`
   - `ALLOWED_ORIGIN` — адрес сайта из шага 3 (например `https://nick.github.io`)
3. **Сайт.** Создай репозиторий на GitHub, залей все файлы, кроме `worker.js`. Settings → Pages → Branch: main → Save.
4. В `config.js` впиши `endpoint: "https://имя-воркера.твой-ник.workers.dev"`.

Для быстрого теста можно вместо воркера вписать вебхук в `directWebhook`, но на публичном сайте так не делай: ссылку увидит любой.

## Что умеет
- поля подсвечены прямо на бланке, обязательные проверяются;
- звание, должность и имя отправителя запоминаются в браузере;
- подпись генерируется по имени (у одного имени она всегда одинаковая), печать накладывается автоматически, её можно отключить;
- «Васильев З.» под подписью собирается из имени сам;
- в «Приложение» вставляется ссылка на боди-камеру и при желании другие материалы;
- номер и дата подставляются сами: номер — только подсказка (следующий свободный), его можно исправить прямо на бланке;
- кнопка «Скачать PNG» без отправки.

## Админка документов
Все маршруты `/admin/*` требуют `Authorization: Bearer <ADMIN_TOKEN>`.
- `GET/PATCH/DELETE /admin/orders`, `GET/POST /admin/seq` — приказы ВГ/ПР и следующий номер.
- `GET /admin/papers?kind=raport|promo|week&q=…`, `PATCH /admin/papers`, `DELETE /admin/papers?id=` — бланки ВП/ПВ/ОТ: имя, звание, паспорт, примечание.
- `GET/POST /admin/paper-seq` — следующий номер для каждого вида бланка.

В `PATCH` номер меняется только если передать `num` (цифры); префикс собирается в базе, другие записи не перенумеровываются, занятый номер не выдаётся.

## Номера документов
- `GET /suggest?kind=order|raport|promo|week` (для приказа ещё `&type=pred|vyg`), нужен вход через Discord. Отдаёт `{num, digits}` — следующий свободный номер; ничего не занимает.
- `POST /` (приказ, JSON; то же по `POST /order`) и `POST /paper` принимают необязательный `num`: цифры или «ВГ-0004». Префикс всегда ставит база по виду документа (через `char()`), диапазон 1–9999.
- Без `num` номер выдаётся как раньше, следующий свободный. Занятый номер того же вида — ответ 409, строка не пишется, счётчик не двигается, в Discord ничего не уходит.
- Номер выше счётчика двигает счётчик (дальше предлагается следующий за ним); номер из пропуска счётчик не трогает.
- На сайте номер записывается в базу при «Скачать PNG» или «Отправить», картинка и сообщение в Discord берут именно его. При 409 поле получает свежую подсказку, остальной бланк не трогается.
